## 2. 节奏数值冻结令（本结项的核心动作）

**冻结对象**：`RULES` 全部——解锁阈值 20/60/145、恒计分封顶 26、繁荣度公式（P1 闲置不计分 / P2 民居按入住率 / P3 解锁粘性）、市税参数、造价表、产出/消耗速率、迁入节拍 0.2 户/tick。

**例外条款**：
1. 内容系统落地或 N2 重启时，整体重新标定（D1′ 挂起条款：1260 与 P2 内容量绑定）；
2. bug 级修复（非体验调参）不受限，但改动后须重跑 115+33 全绿。

**依据**（为什么必须冻结）：
- 余量贴线：V2=1.0 / V1=0.74，任何降分/提阈值改动直接翻红，且收益已被实测证明≈0；
- M9 恒 99.6% 已无区分能力，调参失去观测仪表；
- N2 首期双向独立复放判定「参数层无解」；
- 「组合拳是组合，不能拆」（HANDOVER §6.1 D-P1′ 条目）；
- 协议侧已衔接：规则 4 自 v1.3 起不再预置杠杆数字。

## 3. P2 启动：主线排序

### 3.1 第一棒：美术方向定调（前置一切内容系统）

- **候选**：A 水墨国风（契合宋代市井题材）/ B 像素 / C 延续灰盒
- **为什么先行**：① 空转时段「屏幕上无可看之物」本身是体验缺口（D-1 的体感面）；② 所有后续内容系统的视觉语言依赖此决策；③ 这是成本最低、影响面最大的不可逆决策
- **交付物**：风格定位 1 页 + 核心建筑/地形视觉样张

### 3.2 第二棒：UX-3 新手引导补丁（不动数值基线）

- **立项依据**：D-2（169~220 vs 57~64，两位新手独立复现，普遍性已确认）
- **验收判据**：补丁后 2 局新玩家试玩，Lv2→Lv3 徘徊段压至 **≤100 tick**（熟练 57~64 留余量），且不破冻结令
- **方案要点（设计草案，动代码前需单独评审确认）**：检查点式提示——繁荣度增长停滞 N tick 触发「商业建筑才产铜钱」类提示；住房数显著多于商业时触发「住房过度建设」提示
- **明确不做**：不碰阈值与公式；不做强制引导锁操作

### 3.3 第三棒：内容系统三选一（不并行）

- **候选**：事件系统 / 名士系统 / 科技树（01 §4.2 Out-of-Scope 解除顺序）
- **选择标准**：① 决策密度增量（直接对症 D-1：N2 病根=决策密度不足，1260 tick 愿景需约 84 次决策支撑）；② 与美术管线耦合度；③ 机制验证成本
- 1260 tick 愿景目标随内容落地重新标定

### 3.4 本阶段明确不做

- N2 参数层实验（已判无解，D-N2-7/8 维持暂缓，授权保留）
- `humanRound3Bot × O6′` 复放（半天工作量，但 D1′ 双轨制下其支撑的「熟练落点 288~330」已不参与判定——降级为可选，不做不阻塞任何事）
