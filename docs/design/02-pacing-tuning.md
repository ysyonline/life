## 1. 根因分析：三条线索逐一验证

### 线索 ① 闲置建筑刷分口 —— **证实，是主因，但要和「空屋计分」并案看**

用真人第 2 局终局快照（tick 380 通关，49 座建筑、仅 8 户、劳力需求 27）做繁荣度分解：

| 分项 | 计算 | 得分 |
|---|---|---|
| 恒计分项（农田7+林场6+茅舍7+瓦屋3+粮仓2） | 14+12+7+9+4 | 46 |
| 生产建筑静态分（磨坊4+食肆17+木匠铺3） | 16+85+12 | 113 |
| 静态总分 | | **159** |
| 实际繁荣度 | | **101.6** |
| ⇒ 闲置折损反推 | (159−101.6)/0.7 ≈ 82 分建筑闲置，×0.3 | **闲置白送 ≈ 24.6 分** |

人口只有 8 户，意味着合法路线下最多支撑约 4 座磨坊 + 4 座商业运转；玩家却靠 14 座闲置食肆 + 3 座闲置木匠铺白拿 24.6 分——**占通关 100 分的 1/4，且完全绕过了「劳力迁入 0.2 户/tick」这个设计好的节奏总闸门**。这就是为什么真人（344.5 tick）比最优 bot（504 tick）还快：bot 老老实实养人口，真人抄了近路。

**但推演证明：只堵闲置系数不够。** 把闲置系数 0.3→0 后，真人画像 bot 虽然永远卡在 77 分，但终局囤积 **26069 铜钱**无处花——只要玩家发现「空茅舍恒计 1 分」（设计案 7.6 遗留口子），立刻转向买空茅舍：空茅舍刷分 bot 在「仅闲置=0」下仍 **732 tick 通关**（比 21 分钟目标快 42%）。

**结论：主因是同一个设计缺陷的两个口子——「繁荣度不要求城市是活的」。** 闲置计 0.3 是一口，空屋全额计分是另一口。只堵任何一口，压力都会从另一口漏出。

### 线索 ② 铜钱复利 + 市税正反馈 —— **证实为放大器，是次因，不动**

商业 +3 钱/tick/座的复利确实是刷分路线的资金来源（第 2 局后期钱多到大半闲置食肆都靠它买）。但：① 复利引擎本身是核心体验「规模化扩张爽感」的载体，bot 合法路线同样依赖它；② 堵掉计分口子后，复利只能加速「养活的城市」，无法再购买分数——它从「绕过器」降级为「加速器」；③ 设计案 8.5 确立的食肆对市税 6× 效率比是经济结构支柱，动它会破坏已验证的激励层级。**判定：不调整任何经济速率。**

### 线索 ③ 目标值口径 —— **部分证实，分里程碑处理**

- **Lv3（780）/Lv4（1260）目标：堵口后成立，不改。** 这两个目标建立在「建筑必须运转」假设上——组合拳恰好让假设重新为真。bot 合法路线 504 tick 作为最优下限，普通玩家 2~2.5 倍于 bot ≈ 1000~1260，与 1260 目标吻合。
- **Lv2（300）目标：口径错误，建议下修。** 真人首局（含学操作）57~91 tick 到 Lv2，此处无刷分口可用（Lv1 没有商业建筑），偏快的真实原因是：240 钱 + 60 木的初始存量可直接买 20 分，而目标假设的「探索与布局约 4 分钟」在灰盒即时放置 + 仅 4 种建筑的 Lv1 里不存在。这不是经济问题，是目标设定问题。**不建议为凑 300 tick 去削初始资金**——240 的构成（180 核心 + 60 缓冲）承载 v0.3 的误操作容错设计，动了风险大于收益。

### 根因结论（一句话）

**节奏偏快 4 倍的主因是繁荣度公式不区分「活着的城市」与「建筑的尸体」——闲置 0.3 与空屋全额两个口子让玩家用铜钱直接购买繁荣度、绕过人口/劳力这个节奏总闸门；铜钱复利只是放大器；Lv2 的 5 分钟目标本身口径错误需下修，Lv3/Lv4 目标堵口后自动成立。**

## 2. 调参组合拳

设计原则（与任务约束对齐）：**修口子，不注全局水**。所有改动集中在繁荣度公式语义，不动任何生产/消耗/造价/税率/迁入速率——保住已被真人验证的「单瓶颈轮换」「断链自愈」体验，也保住设计案 8.5 的 6× 经济结构。

### 必须项（P1~P3，缺一不可）

| # | 参数/规则 | 从 | 到 | 针对 |
|---|---|---|---|---|
| **P1** | `rules.js prosperityCoef.idle` | 0.3 | **0（闲置建筑不计繁荣度）** | 闲置刷分口 |
| **P2** | `computeProsperity` 公式扩展 | 繁荣度 = Σ 基础分 × 运转系数 | **生产/存储建筑：运转才计分（P1）；民居：基础分 × 入住率，入住率 = min(1, 在城户数 / 民居总容量)** | 空屋刷分口 |
| **P3** | 解锁判定 | `computeLevel` 按瞬时繁荣度，可回落重锁 | **解锁粘性：state 记录历史最高等级 `maxLevel`，建造菜单按 `maxLevel` 判定；繁荣度进度条仍按瞬时值** | P1/P2 放大繁荣度波动后的回落重锁体验风险 |

**P2 的完整公式（单一公式原则不变，仍为透明可算）：**

```
繁荣度 = Σ[生产/存储建筑：基础分 × (闲置 ? 0 : 1)]
       + Σ[民居：基础分] × min(1, 在城户数 / 民居总容量)   // 容量为 0 时入住率按 0
```

**P2 设计理由**：
- 「入住率」是玩家零学习成本的概念，且让 Lv1 起「养人口」就有了分数意义（现在茅舍只是门票）。
- 自带良性性质——**空屋中性化**：拆掉空置民居，入住率上升恰好对冲分值减少（7 茅舍 8 户：7×0.57≈4.0；拆 3 座剩 4 座全住满：4×1.0=4.0），不产生「拆房刷分」或「空屋惩罚」的扭曲激励。
- 农田/林场本就不占劳力、恒计分，且受沃土/林地地形格数硬封顶（全图约可建 20~25 座原料建筑 ≈ 40~50 分），天然有界，无需处理。
- 粮仓仍恒计 2 分——它是已知的残余口子，但推演证明其**不构成主导策略**（见 3.3），挂观测项即可。

**P3 设计理由**：现行规则下回落重锁已经真实发生过（第 2 局 tick 219 到 Lv3，tick 240 繁荣度跌回 47.5 → 木匠铺重锁）。P1/P2 后断链引起的繁荣度振幅变大（断链建筑从 0.3 变 0），若无粘性，玩家会遇到「刚解锁又锁回去」——在真人已反馈「不大明白怎么通关」的背景下，这是不可接受的体验回退。粘性与 5.5「惩罚只作用于节奏」同向：断链惩罚落在繁荣度数值与进度条上，不回收已解锁内容。

## 4. 不变量自检（设计案 5.5）

**声明：本方案不触碰任何资源的再生入口，「无吸收态」不变量完整保留。**

逐条核对：

1. **流量防死锁未动**：市税 0.05/户/tick、商业产出、拆除返还 50%、保底户 1、农田/林场免劳力——全部不变。铜钱在 M=0 处导数仍 ≥0.05 > 0，0 仍是可穿越下界；设计案 5.4《不可恢复态审计表》五行全部继续成立（改动不涉及任何一行）。
2. **繁荣度是「评价指标」不是「资源」**：P1/P2 只改变繁荣度的计算，繁荣度回落不阻断任何资源流、不摧毁任何存量；P3 让解锁只升不降，进一步排除了「繁荣度回落 → 重锁 → 无法建造 → 死锁」的理论路径（虽然该路径在现行规则下也不致死了，粘性把它从规则上彻底封死）。
3. **资金归零可恢复性不受影响**：钱 0 时市税涓流、拆建筑返还、保底户开磨三条恢复路径与繁荣度公式零耦合。
4. **无新吸收态引入**：入住率 = 户数/容量，户数有保底 1 户下界、迁入有食安全线上界，均无新循环依赖；入住率只影响分数显示与解锁进度，不反馈进任何生产环节。
5. **5.5 其余原则**：单瓶颈（开局缺木→中期缺劳力/食轮换）不变——组合拳反而**强化**了劳力瓶颈的统治地位；反馈即时性不变（3 tick 内数字变化）；容错不变（断链仍只影响节奏）。

**存档兼容**：纯公式改动，无存档状态迁移，saveVersion 不变。

## 6. 伴随 UX 建议（不阻塞本任务，可并入实施）

针对判定报告第 6 节的体验发现：

- **UX-1（建议随 P1/P2 一起做）**：繁荣度进度条旁加一行小字「断链/闲置建筑不计繁荣度」；民居信息面板显示入住率。规则变了必须让玩家看得见，否则 P1/P2 会被读成「游戏出 bug 不给我分」。
- **UX-2（建议做）**：Lv4 达成时全屏 toast 强化（如「繁华大成——杂货摊已解锁」）并在建造菜单高亮杂货摊，回应两局玩家「不大明白怎么通关」的反馈。纯 UI 层，无数值风险。
- **UX-3（移交 P2 议题，本轮不做）**：通关后城市自然衰退无失败态——竖切片「单局无失败」原则不变；P2 可考虑胜利结算画面或「维持繁荣 N 分钟」的无尽目标。记录待用户排期。
