## 1. 问题定义：B 的目标感缺口在哪一段、缺的是什么

### 1.1 证据定位（真人试玩，A4 复测 `215210`，d 判定书 §1/§2/§4）

| 观测项 | 读数 | 口径 |
|---|---|---|
| 徘徊段 | Lv2@132 → Lv3@401 = **269 tick** | 真人 B 首局，遥测 30 tick 粒度 |
| 自述 | 「啥点都没反应了 / 差点以为结束了」 | 挣扎期访谈原话 |
| 同期状态 | money 1~25；tick 300 繁荣 18 < 20 **跌回 Lv1**；断链 25 次 | d 判定书 §2 |
| 病灶定性 | **经济自陷型**（240 启动资金全押无收入建筑），已由 T1 文案补丁（D-甲）处理"没钱怎么办" | d 判定书 §3、§5 |

**缺口定位：tick ~300~400，即 Lv2→Lv3 徘徊段的中后段**——B 已拿到 T1 提示（@182）、已知道要建食肆、正在靠市税 0.2/tick + 拆建返还缓慢自救。此时他的问题不是"不知道机制"（T1 文案已覆盖），也不是"提示太晚"（触发及时），而是：

1. **终局感缺失**：不知道这个游戏有 Lv4 通关点、自己当前在四级阶梯的哪一级、离"赢"还有多远。「差点以为结束了」是这句话的直接证据——他连"游戏是否还在进行"都无法确认。
2. **进展不可感**：自救期繁荣度在 18~40 间低速抖动（60 tick Δ 个位数），进度条视觉上近乎静止。「啥点都没反应了」对应的是**反馈真空**，不是信息缺失。

### 1.2 与既有缺口的边界（防重复立项）

| 缺口 | 归属 | 状态 |
|---|---|---|
| 不知道要建食肆（商业缺失） | T1 触发 | ✅ 已覆盖，@182 及时触发 |
| 不知道食肆要食链（机制因果） | T1 文案 a | ✅ 已覆盖 |
| 提示处方买不起（恢复路径） | T1 文案 D-甲补丁 | ✅ 已覆盖 |
| **不知道全局目标 / 离赢多远 / 游戏是否还在响应** | **c（本评估对象）** | ❌ 现行体系无任何覆盖——T0/T1/T2 全部是**纠偏型**提示（出事才弹），没有任何**目标型**常驻展示 |

最后一条是 c 的正当性所在：现行引导是"坏了告诉你怎么修"，B 的缺口是"没坏的时候告诉我往哪走"。两者正交。

## 2. 方案形态（3 候选）

### 形态甲：等级阶梯全景（终局感）

- **交互草描**：HUD 繁荣度条上方/侧方加一行静态阶梯标识：`Lv1 ●— Lv2 ●— Lv3 ○— Lv4 ○（通关）`，当前级高亮，已过高亮实心，未到空心；Lv4 标注「通关」。纯文本/符号，不新增组件。
- **信息来源**：全部现成——`RULES.unlockThresholds = [0, 20, 60, 145]`（rules.js:17，只读）、`state.level` / `state.maxLevel`。hud.js:82 已经在读同一个 `ths` 数组，形态甲只是把"下一级"扩展成"全阶梯"。
- **与 T0/T1/T2 关系**：**互补**。常驻被动展示，无触发逻辑，不占提示条配额（A5 单局 ≤3 条不受影响），不与 T1/T2 抢 HUD 下方横幅位。
- **改动面**：`hud.js` update() 内 ~10 行 + style.css 少量。**判定逻辑零新增**（无玩法判定，纯展示映射），因此无 core/UI 分层争议。

### 形态乙：进度差额数字化（进展可感）

- **交互草描**：现有「下级 60 解锁：杂货摊」补差额：「下级 60（还差 36 分）解锁：杂货摊」。繁荣度每跳 0.1 数字就变——**让低速爬升在视觉上可确认**，直接回应「啥点都没反应了」。
- **信息来源**：现成——hud.js:84-86 已算出 `next`/`prev`，差额 = `next − p`，一行字符串拼接。
- **与 T0/T1/T2 关系**：**互补**，且有一个间接收益：T1 触发后玩家在慢速攒钱攒分期，差额数字的持续变化是"提示正在生效"的正反馈，延长提示的有效期。
- **改动面**：`hud.js` 1~3 行 + 可能需同步 1~2 条 HUD 断言测试。

### 形态丙：阶段性小目标任务化（08 文档 c 的原始形态）

- **交互草描**：HUD 常驻「当前小目标：攒 50 钱建一座食肆（食肆运转才计分）」，完成后换成下一个（如「让食肆不断粮运转 60 tick」）。目标完成打勾 + 轻量庆祝反馈。
- **信息来源**：目标完成判定需读玩法状态（money、eateryCount、断链状态）——按分层纪律，**判定落 core**（新谓词，与 hints.js 同纪律），展示落 UI。
- **与 T0/T1/T2 关系**：**部分重复**。T1 已经在说"建食肆 + 食从农田→磨坊来"；形态丙把同一件事变成"任务"，信息内容高度重叠，差异只在呈现框架（任务化 vs 提示化）。
- **改动面**：即 08 §3c 评估的全套——UI 新组件 + 目标状态机 + 遥测新字段 + 协议升版 + 判定带，**3~5 天**。

## 3. 证据判定：c 能否解决 B 的缺口？

**关键事实**：B 挣扎期间，HUD 上**一直显示着**「LvX 繁荣 xx.x」+ 进度条 +「下级 60 解锁：杂货摊」（hud.js:81-92 现行实现）。他说出「差点以为结束了」时，"下一级是什么"这个信息**就在屏幕上**。

| 形态 | 判定 | 理由 |
|---|---|---|
| 甲（阶梯全景） | **能（对终局感缺口）** | B 的原话「差点以为结束了」是**终局感**问题——他不知道有 Lv4、不知道自己在阶梯上的位置、无法确认游戏还在进行。形态甲是唯一直接回答"全局有多远/我在哪/游戏没死"的形态。现行 HUD 只有"下一级"，没有"终点"，这正是已展示信息里**唯一缺的那块**。 |
| 乙（差额数字化） | **部分** | 对「啥点都没反应了」：繁荣度冻结时差额也不动，不能伪造进展；但 B 的自救期繁荣度并非完全冻结（18→40 段在动），差额跳动能把"肉眼不可见的 0.1 级变化"变成可确认的数字反馈，缓解反馈真空。**对终局感无贡献**——它回答"差多少"，不回答"总共多远"。 |
| 丙（小目标任务化） | **部分（且证据不足）** | 理论上"当前小目标"同时回答"干什么"和"往哪走"，是覆盖最全的形态。但：① B 案例里"干什么"已由 T1 覆盖（他 @182 就知道要建食肆，缺的是钱和全局感）；② n=1 且与"经济自陷/机制不懂"两层卡点混杂，**无法归因目标感单独贡献多少**（08 §3c 原文判断，d 复测后依然成立——d 只新增了 1 个混杂样本，没有把目标感从混杂中分离出来）；③ 08 §10.3 的判定路径说"若瓶颈为经济则 c 优先级上调"——d 的实际结果是瓶颈为经济**且已被文案补丁处理**，该上调条件并未按原设想触发。 |

**诚实标注 c 不覆盖的部分**：
- **经济自陷本身**：c 的任何形态都不解决"钱全押错建筑"。该缺口已由 D-甲文案补丁处理，c 不重复认领。
- **等级回落的双重打击**（B tick 300 跌回 Lv1）：d 判定书 §4-2 已建议单列议题。形态甲的阶梯全景会让"回落"更显眼——这是双刃剑（见 §4 风险 R-c3），不属 c 能"解决"的范围。
- **超建食肆模式**（11 座致断粮，与 P5 同款）：属断链/产能平衡认知，c 不覆盖。

## 4. 成本与风险

### 4.1 工作量估计

| 形态 | 工期 | 改动面 | 协议/遥测 | 冻结令 |
|---|---|---|---|---|
| 甲 + 乙（合并实施） | **~1 天**（含文案/样式微调 + 测试同步） | `hud.js` ~15 行 + `style.css` 少量 + 可能 1~2 条 HUD 测试断言同步 | **零协议升版、零遥测新字段**（纯展示，hud.js 已在读 `unlockThresholds`） | **零触碰**（只读 RULES，与 hud.js 现状同级） |
| 丙 | 3~5 天（08 §3c 原估，本评估复核后维持） | UI 新组件 + core 目标谓词 + 状态机 + 遥测字段 + 协议升 v1.6 + 判定带 | 需升版 | 不碰数值，但判定带属新增 core 面 |

### 4.2 对 142+33 测试网的影响

- **甲+乙**：`hud.js` 文本输出变化，若有测试断言「下级 60 解锁」精确字符串则需同步（预计 ≤2 条）。hints 23 用例、33 条验收探针**零影响**（不碰 hints.js / telemetry.js / simulation.js）。bot 基线 V2 `12/355/605` 不受影响（纯 UI 展示）。
- **丙**：新增 core 谓词需新增单测（估计 6~10 条），遥测 schema 变更需按超集字段纪律处理 + serialize/restore 旧档容忍（C-6 先例），影响面显著大。

### 4.3 误伤熟练玩家风险（UX-3 R1 教训对照）

| 风险 | 甲+乙 | 丙 |
|---|---|---|
| R1 型误伤（熟练玩家被提示打扰） | **近零**：无触发逻辑，是常驻被动展示。R1 误伤的成因是"触发条件判错"，甲/乙根本没有触发条件。这是相对 T0/T1/T2 的结构性安全优势 | **中**：任务系统若对已完成事项反复播报/庆祝，熟练玩家会觉得被教做事；且常驻「当前小目标」对不需要的玩家是压力源（08 §3c 原文："与'拉节奏不施压'的 UX 定位冲突"） |
| R-c2 信息过时 | 低：阶梯/差额直接从 state 派生，无缓存态 | 中：目标状态机引入会话状态，有 R4 型（读档重发）同类问题 |
| R-c3 回落显化 | **中低**：B 跌回 Lv1 时阶梯全景会让回落更刺眼。缓解：阶梯按 `state.maxLevel` 高亮（已到过的级保持实心，simulation.js:191 已有此语义），回落只影响进度条不影响阶梯——**把"曾经到过"和"现在在哪儿"分开表达**，反而把回落从"惩罚"转成"已知路径的回退" | 同左，且任务回退（目标从"建食肆"退回"攒钱"）挫败感更强 |

## 5. 明确建议

### **变形立项**（三选一之第二项）

| 项 | 建议 |
|---|---|
| 立项内容 | **形态甲 + 形态乙**，合并为一个 HUD 增强任务，~1 天 |
| 不立项内容 | 形态丙（08 文档 c 的原始 3~5 天形态）**转 backlog**，触发再评估的条件：下一轮试玩出现 ≥1 个"经济正常、机制已懂、仍自述迷失"的**非混杂**目标感样本 |
| 排序 | 不阻塞任何关键路径；建议在 P2 美术定调（D-C3）之前或并行，因为它改的是 HUD 文本/符号层，美术定调后需二次贴合的成本低 |

### 理由（对应 08 §3c 原始顾虑的逐条回应）

1. **n=1 混杂样本的顾虑依然成立 → 所以不做丙**。d 复测只把 B 从"混杂"重新定性为"经济自陷 + 目标感并存"，目标感的独立贡献仍不可归因。但——
2. **甲+乙的成本结构改变了赌局**：08 的"暂不实施"是建立在"c = 3~5 天 + 协议升版"的代价评估上的。甲+乙把代价压到 ~1 天、零协议、零触发逻辑、近零误伤风险，**期望收益/代价比完全反转**——用 1 天赌 n=1 证据，划算；用 3~5 天赌，不划算。
3. **甲直击 B 的原话**：「差点以为结束了」的反面是"知道有终点、知道自己在哪"。这是现行 HUD（只有"下一级"没有"全局"）的确切空洞，不是臆造需求。
4. **丙不做不是因为没用，是因为证据不够 + 边界冲突**：它与 T1 信息重叠、触碰「不提示最优建造顺序/只讲机制因果」的 07 §2 设计边界（任务化本质是行动指向，比 T0 的边界张力更大），且需要协议升版。这些代价需要非混杂样本才能正当化。

### 落地约束（若拍板通过）

- 甲/乙均落 `hud.js` + `style.css`，**零 core 改动**（无玩法判定，纯展示映射，分层纪律天然满足）；
- 阶梯高亮用 `maxLevel` 而非 `level`（R-c3 缓解）；
- 差额文案控制在单行内（沿用 a 条款的横幅长度教训）；
- 遥测/协议不动；A4 判据不动；D-C1 冻结令零触碰（`git diff rules.js buildings.js` 为空作为验收行）。
