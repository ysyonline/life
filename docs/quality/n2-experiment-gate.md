## 1. 双 Gate 复检流程（防贴线翻红）

### 1.1 为什么这是硬约束

V2 余量 **1.0 分**、V1 余量 **0.739 分**——这不是「还有 1 分的容错」，而是**「任何削分 / 抬阈值 / 占地挤占类改动都极易跨线」**。历史教训：

- P-1′ 原案（封顶 24 + Lv4 150）在**当时**的 bot 上 V2/V1 双红（8000 tick 到不了 Lv4）；
- 现行 O6′（封顶 26 + Lv4 145）是三方交叉后**唯一存活**的一格（HANDOVER §6.0）；
- N2 的 ③（压 `baseCaps` / 改 `granaryBonus`）会逼迫 bot 多建粮仓，而**粮仓属恒计分类、已被封顶 26 锁死**——多建的粮仓在封顶已满时**净贡献 0 分**却占地、占钱、占建造节拍 ⇒ 直接压低可达繁荣度上限（详见 §7 预判）。

**⇒ 结论：N2 参数档落地前，双 Gate 必须重跑；读数翻红时，必须按 §1.5 的流程走，不得绕过。**

### 1.3 判红读数表（S2 输出怎么判）

| Gate | 读数 | 绿 | 警示（CONCERNS） | 红（FAIL） |
|---|---|---|---|---|
| **V2** 初始资源自然通关 | Lv4 到达 tick、最高繁荣 maxP | Lv4 ≠ null 且 **余量 ≥ 1.0 分**（maxP ≥ 146.0） | Lv4 ≠ null 但 **余量 < 0.5 分**（maxP < 145.5）或 tick > 1000 | **Lv4 = null**（2000 tick 未达） |
| **V1** 注入铜钱对照 | Lv4 到达 tick、maxP | Lv4 ≠ null 且 **余量 ≥ 0.74 分**（maxP ≥ 145.74） | Lv4 ≠ null 但 **余量 < 0.5 分**（maxP < 145.5） | **Lv4 = null** |
| R-bot3 旧 bot 看门狗 | 12 / 401 / null、V1 null | 逐字复现 | — | 任何一项漂移 ⇒ **无意漂移即红**（HANDOVER §5） |

> **余量警示线 0.5 分**为本轮建议值（DP-3）：现行 1.0 / 0.739 已是历史最紧，若 N2 把余量压到 0.5 分以下，则**任何后续微调（含美术期内容增量）都会翻红**，不可接受为稳态。

> **⚠ 仓容类改动的风险排序（design-strategist 05 §2.4 实测，我采纳并写入判据）**：
> **wood 侧比 grain 侧危险得多**——延伸候选「木仓容 60」会把 **V1 余量从 0.739 压到 0.31**（V1 = 530、最高繁荣 145.31），接近现行余量的 1/2；「木仓容 100」也把余量压到 0.38，且 bot 会改为多建林场**绕开**约束（无事可做帧反而升到 80.4%）。
> ⇒ **判据**：③ 若延伸到 wood 侧，须**单独提高门槛**——V1 余量**不得 < 0.6 分**（严于通用 0.5 线），且必须同时验证「bot 是否可绕开约束」（观察终局 `forest` 座数是否异常上升）。grain 侧沿用通用 0.5 线即可。

### 1.4 判红的三种性质必须先分清楚（这是最容易被混淆的一步）

| 现象 | 性质 | 处置 |
|---|---|---|
| V2/V1 到得了 Lv4，但 tick / maxP 漂移 | **基准漂移** | 走 §1.5 分支 A（基准升版） |
| V2/V1 **2000 tick 到不了 Lv4**（null） | **机制不可达** | 走 §1.5 分支 B（否决该参数档，回设计侧重做） |
| **V2 绿 + V1 红**（土地/仓容类改动的典型形态） | **约束迁移，非不可达** | 判 **CONCERNS + 强制人工裁定**（见下方 D-N2-10 判据），**不得直接判 FAIL** |
| 读数漂移是 bot 自身能力缺陷造成（如食流死结、不会拆建筑） | **工具缺陷** | 走 §1.5 分支 C（先修 harness 再测，不得用缺陷读数否决方案） |

> **D-N2-10 判据（答复 design-strategist，已对齐口径）**：V1「注入铜钱」的语义是**隔离验证 Lv2→Lv4 链路可走通**，不是"模拟钱无限的玩法"。土地/仓容类改动**必然**先撞 V1（因为它只解除铜钱约束，不解除土地/仓容约束）——这是**约束迁移**，不是链路不可达。故：
> - **V2 绿 + V1 红 ⇒ CONCERNS + 强制人工裁定**（须写明：新约束落在哪个维度、该维度是否为设计意图中的约束力、V2 绿已证明链路仍通）；
> - **V1 红 + V2 也红 ⇒ FAIL**（那才是真不可达）；
> - **任何情况下不得通过放宽 V1 用例断言让它变绿**（§7.2 红线）。
> 本条**取代**「V1 红 = 该档不可交付」的简单二分——后者会把所有土地/仓容类方案在第一道 Gate 就误杀。

> **分支 C 的历史教训（必读）**：第 2 轮判定报告 §6.7 已证明——P-1′ 与纯阈值 250 的"不可达"**不是游戏不可达，是当时 bot 的写死配额造出食流死结**（人类拆建筑即可脱困）。**在排除"bot 自身缺陷"之前，不得用 null 读数否决任何 N2 方案。**
> **本轮判据**：出现 null 时，必须先回答「这是新约束对**所有**路线都致命，还是只对这条贪心启发式致命？」——回答手段是 §2 的工厂镇复放（另一条完全不同构型的路线）与 `frag` 脆弱性探针。

### 1.5 红了怎么办（三条分支，红线不可越）

**🔴 红线（HANDOVER §7.2，本框架重申）**：**任何人不得为了让自己通过而修改 `tests/verification/`**。验收套件是独立基准，改它等于自己给自己判卷。**本条对 QA 同样生效——QA 只出判据与复核，不执行验收基准的修改。**

**分支 A：基准升版（读数漂移，方案仍可达）**

1. **三方独立交叉**：设计侧 harness / 工程侧 harness / QA harness 各自独立复放新读数，三方一致才入档（HANDOVER §7.10）。
2. **确认是有意调整**：显式写明「哪个参数从 X 改到 Y ⇒ 读数从 A 变 B」，并确认该变化是 N2 的设计目的（例：土地收紧 ⇒ V2 tick 必然上升）。
3. **归档 pre-N2 读数注释**：在 `tests/verification/progression.test.js` 的注释里追加 pre-N2 基线（commit 号 + 旧读数 + 变更参数），**旧读数不得删除**。
4. **用户授权**：由主理人向用户申请「基准升版」授权（D0 时代已确立此流程：授权 + 新旧并行 + 先复现基线）。
5. **执行**：**由工程侧**改钉住值与注释；QA 复核重跑 33/33 绿。
6. **同步**：`tests/config.test.js`（D10 快照）、`docs/quality/playtest-protocol.md`（若动阈值）、`docs/HANDOVER.md` §5 基线表、`docs/design/02-pacing-tuning.md` §3.1 验收区间——四处必须同批更新，**缺一处即视作升版未完成**。

**分支 B：否决（2000 tick 不可达，且非 bot 缺陷）**

- 判 **FAIL**，方案回设计侧重做参数。
- 必须附：① 失败机理（是卡在哪个约束？）；② 与 §1.4 分支 C 的排除证据（工厂镇复放是否同样不可达）。

**分支 C：工具缺陷（bot/harness 能力问题）**

- 判 **CONCERNS**，不由 N2 参数背锅。
- 处置：先修 harness（扩建造优先级 / 加自救规则），修完重跑 S1~S3；修 harness 属工程侧，需另开任务，不计入 N2 判定。

### 1.6 一条额外的耦合禁令

**N2 不得顺手动 `unlockThresholds` 或 `prosperityPassiveCap`。** 若某个 N2 参数档"必须同时动阈值/封顶才能过双 Gate"，则视为 **N2 与 P-1′ 耦合**——此时不得由 N2 侧自行消化，须回主理人裁定拆分（P-1′ 是已拍板已提交的卫生性改动，其参数属独立决策面）。

### 2.3 「解法必须对最优路线生效」的判据

**⚠ 前置缺口（必须补，否则本条无法判定）**：目前**没有工厂镇路线的稀缺帧占比实测基线**——04 文档只给出「劳力利用率 ~100%」，未给逐帧稀缺读数；`replay2` 也未输出库存轨迹与放置失败计数。

> **前置任务（DP-5，需授权）**：在 N2 参数落地**之前**，先补采工厂镇 O6′ 基线档案：
> ① 逐帧 M9 同口径稀缺标记占比（§3 口径）；② 逐 tick 粮/食库存轨迹（触顶 / 触底帧占比）；③ 放置失败（无可用地）帧占比；④ 活跃集（活跃磨坊/食肆数）；⑤ 终局占地格数 / 可用地格数。
> 工程量小（扩 `replay2` 输出，不动 `src/`），**属工程侧执行，QA 出字段清单并复核**。

**「生效」判据（建议值，待拍板 DP-2；满足任一即算生效）**

| # | 判据 | 阈值（建议） |
|---|---|---|
| **E1** | 工厂镇 M9 同口径稀缺帧占比相对基线**上升**（即空转下降） | Δ ≥ **20 个百分点** |
| **E2** | 复放轨迹出现**新约束维度绑定**：容量约束（粮/食库存触顶或触底）或 土地约束（放置失败） | 该类帧占 Lv3→Lv4 窗口 **≥ 30%**（容量）/ **≥ 20%**（土地） |
| **E3** | 终局构成出现**解法指向的结构响应**：如 `granary` 由 0 → **≥ 2 座**，或终局占地 / 可用地比 **≥ 45%** | — |

- **三者皆不满足 ⇒ 判「解法对最优路线未生效」⇒ FAIL**（不是 CONCERNS——D-N2-5 是拍板通过的硬要求，只对慢路线有效的解法不算解法）。
- E1 在工厂镇基线空转已很低时会失效，此时以 E2/E3 为准（**这正是"先补基线档案"的意义**）。

### 2.4 反向约束（D-N2-5 附条件 4）：解法不得摧毁最优路线

> **⚠ 本节阈值为 QA 建议值，无实测锚点，须用户拍板（DP-1）。** 现状是：全项目至今没有任何一次"机制改动后工厂镇读数"的实测，因此只能由锚点外推。

**建议主判据（双口径；基准 = O6′ 工厂镇 N=∞ 226 / N=1 274）**

## 3. M9 / M9′ 空转判据口径

>
> **M9（空转帧占比 = 1 − 缺料/缺人帧占比）在 O6′ 下已丧失区分能力**：Lv3→Lv4 窗口实测缺料 **0%**、缺人 **0%** ⇒ M9 恒等于 **99.6%**，压 `baseCaps.grain` 到 40、可用地压到 ×0.75 **都一字不动**。机理：理性玩家（与 bot）会主动避开闲置，所以「缺料/缺人」永远 ≈ 0 —— **M9 测的不是"玩家有没有事做"**。

### 3.1 计算公式（唯一定义，v1.3 协议 §1.2 M9 的可执行化）

数据源：`src/core/telemetry.js` 的 `scarcity.materialTicks` / `scarcity.laborTicks`（**逐帧**、记录出现该稀缺的全部 tick 号；实现见 telemetry.js:73-84，读 `b.idle` / `b.idleReason`）。

```
T                = 分析窗口的 tick 总数
U                = materialTicks ∪ laborTicks        // 并集，两数组可有交集（同 tick 双稀缺）
|U|              = |A| + |B| − |A ∩ B|
M9(窗口)         = 1 − |U ∩ 窗口| / T                 // 无稀缺约束帧占比（空转帧占比）
稀缺帧占比(窗口) = |U ∩ 窗口| / T                     // 与 M9 互补，本框架统一用这一个方向（↑ = 改善）
```

| 窗口 | 定义 | 用途 |
|---|---|---|
| **全窗口** | tick 1 ~ `milestones.lv4` | 全局体验口径 |
| **Lv3→Lv4 段** | `milestones.lv3` ~ `milestones.lv4` | **N2 的主判据窗口**（空转集中在此段） |

> 分母口径须在分析脚本里**显式声明并写进判定报告**；不得用 `samples` 帧数代替 tick 数（samples 是 30 tick 一帧的采样，与逐帧数组不同量纲——这是本框架最容易出的低级错误）。

### 3.2 三条口径纪律（违反即读数作废）

1. **M9 与"综合稀缺口径"不可混用。**
   - **M9（本框架口径）**：只用 `idleReason ∈ {material, labor}` —— 捕捉"建筑因缺料/缺人而闲置"。
   - **综合稀缺口径**（判定报告附录 D.2 用的）：还含住房满员、食 ≤ 10、木 = 0、粮 = 0、钱 < 15、近 30 tick 无断链。
   - ⇒ 引用真人第 3/4 局的 **100% / 0%** 时必须标注「**综合稀缺口径**」，**不得与 M9 并列相减**。两者数值不可比（同一批数据会给出不同数）。
2. **窗口计数不可相加求并集。** `samples[].scarcityMaterial + scarcityLabor` 会把"同 tick 双稀缺"计两次，**不是**稀缺帧数。求并集必须回到 `materialTicks / laborTicks` 两个 tick 数组。
3. **旧档降级必须显式标注不可用。** `@1.1/@1.2` 旧档 `scarcity` 字段缺失（telemetry.js:224-243 兼容降级为空数组）⇒ M9 **不可计算，标 `不可用`**，**严禁填 0 或按空数组算出 100% 空转**——那是最危险的假值（B3 教训：看起来合法的兜底值比明显的错误值危险得多，HANDOVER §7.7）。

### 3.4 < 40% 的定性：探索目标，不作硬 Gate

- 协议 v1.3 §1.2 与 04 §3.2 已定：**< 40% 是无实测锚点的探索目标**（全部实测配置的最低值为小城模式 **67.3%**，大城 93.1%、新 bot 99.6%）。

**⇒ 关键发现：wood 仓容 100/150 档下，M9′ 反而下降 2.0pp（82.3% → 80.3%），看起来是"空转改善了"；但同期 `forest 10→17`、`carpenter 9→7`、V1 余量 0.74→0.38。**

它的机理是**"用更多上游建筑稀释节拍"**：bot 被逼去铺更多林场，于是"每 tick 有东西可建"，无事可做帧下降——但这**不是新增了需要响应的约束，只是让人更忙**。

> **⚠ 措辞纪律（我方主动收紧，依据 design-strategist 的噪声质疑）**
> **不得**把 ② 的帧占比变化描述为「已证实反向恶化」。理由：**+0.6pp 落在我方自己声明的噪声带之内**，与「改善阈值须高于噪声（−12pp）」是同一条标准，**必须对称适用**。
> ⇒ 可测量结论只写到：**「在双 Gate 可行域内，② 没有任何一档出现超越噪声带的健康改善」**。
> ⇒ 真正的负载证据是**结构性的**：终局构成替代 `farm 10→8` / `carpenter 9→11` ⇒ 约束被绕开。这一条不依赖噪声级读数。

> **⚠ 这是本轮最危险的一条：M9′ 存在"假改善"通道。** 只要给玩家更多"可点的东西"，M9′ 就下降；若 Gate 只看 M9′，这种"更忙而非更有决策"的改动会**骗过 Gate 并被记为 N2 达成**。
>
> **识别判据（满足其二即判「假改善」，不计入改善项）**
> 1. 终局构成中**上游建筑增量 > 基线 +3**（如 wood 档 forest 10 → 17）；
> 2. **V1 余量跌破 0.6**（wood 档实测 0.38 / 0.31）；
> 3. **下游建筑数下降**（wood 档 carpenter 9 → 7，是替代不是扩张）。
>
> **⇒ 硬规则：M9′ 的改善必须与 M10（决策密度）/ M11（无空地失败）/ M12（仓容触顶）联合判定；单一 M9′ 下降不得计入改善项 D1′/D2′。**（已并入 §4.1 表下注与 §4.4 模板）

> **⚠ 硬规则的例外通道（机制层）—— 必须开，否则会误杀 D-N2-7**
>
> 上述三条自动判据**只对「参数型改动」成立**（改数值、构成不变）。**机制层方案（D-N2-7）按定义就是要改变构成**——它的机理是「让玩家把资源投到粮线换人口」，所以「上游增加 + 户数大幅增长」**正是设计意图**，而 `carpenter` 下降是资源竞争下的取舍，**不是"被塞了更多同质操作"**。
>
> ⇒ 若直接套用自动判据，D-N2-7 会命中「条件 1 + 条件 3」⇒ 被判「假改善」⇒ M9′ 的改善不计入 ⇒ **在第一道 Gate 上被自己人误杀**。而它恰是目前唯一命中病因的方案。
>
> **处置**：
> - **机制层方案走人工裁定通道，不套用自动判据**；
> - **裁定关键观测量 = 户数增幅**（建议阈值 **> +25%**）：
>   - D-N2-7 实测 **88 → 125 户（+42%）** ⇒ 真实扩张，改善应计入；
>   - 对照 wood 仓容 150 档 **88 → 94 户（+7%）** ⇒ 参数型绕开，不计入。

> **我方独立复放（2026-10-18，外层近似）**：V2 = **12/341/590**、maxP **148.5**、**125 户 / 102 建筑**、无事可做 **74.6%**、构成 `hut63 / farm14 / mill14 / forest10 / carpenter1**。与 05 §7（D-N2-7 建议）所述 **590 / 74.3% / 125 户 / carpenter 1** 一致 ✓（M9′ 差 0.3pp，属窗口边界差异）。

> 注：wood 仓容为**延伸候选，超 D-N2-2 授权范围**；此处仅作"假改善"机理的证据，不构成 wood 档的实施建议。另：我方探针沿用与 05 文档相同的「每 tick 开始钳制存量」近似（真实实现应在 `addResource` 当场钳制）⇒ **本读数比真实实现宽松，真实咬合只会更强**。

### 4.5 ⚠ 两个正交目标：不得用「拉时长」的失败否定「治空转」

### 6.3 B5（画像面板空值）的根因修复判据

### 6.5 建议：灰盒 A/B 同人对照（B2 未解情况下最强的可得证据）

> **待用户拍板（DP-7）。** 在 B2 短期无法补齐 2 位新玩家时，这是唯一能同时压住"玩家水平"与"学习效应"两个混淆变量的方案。

- **⚠ 诚实声明**：配对设计能控住"人"的变量，但**控不住"首局/次局"的探索成本差异**，因此仍需随机化顺序并在报告里标注局序。
