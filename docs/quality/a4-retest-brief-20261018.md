## 0. 环境（已就绪，无需再操作）

- 服务：`http://localhost:5173`（本次新起的 dev server，旧进程已杀，防 B3′ 指纹滞后）

- 单人单局约 5~8 分钟。两位玩家**不要同时玩同一台机器**（会串数据）。

## 1. 每位玩家的流程（4 步，顺序不能错）

1. **开新局**：页面若已有进度，点 HUD 右下「**重开新局**」→ 确认。⚠ 这一步会清除上一位玩家的采集数据，**必须等上一位导完再点**。
2. **让玩家自己玩**，主持人不碰键盘鼠标。全程只在被问时回答，口径见 §2。
3. **玩家到 Lv3 后**（或他说"差不多了/不好玩/卡住了"），由他继续玩到自然停手或到 Lv4。
4. **导出**：HUD「**试玩数据**」→ 面板填主观项（画像 / 节奏 / 备注）→ 点「**导出 JSON**」→ 文件落到下载目录 `playtest-session-<时间戳>.json`。

## 2. 能说 / 不能说（这条决定数据有效性）

**可以说**
- 「随便玩，没有标准答案，卡住也没关系。」
- 「你想到什么就说什么，我看到你在犹豫会记一下。」
- 界面操作类问题（「怎么缩放」「怎么暂停」）——这是工具，不是玩法。

**绝对不能说**
- ❌ 「你该建食肆了」「农田要先建」——任何指向具体建筑的提示。
- ❌ 「繁荣度是这么算的」——机制解释属于被测内容。
- ❌ 「这个提示是在教你……」——提示是 a+b 的改动本体，不能说破。
- ❌ 玩家卡住时给建议。**卡住就是数据**，尤其要看提示出现后他有没有反应。

如果玩家问「我该干嘛」，标准回答：**「你觉得呢？」** 然后记录他这句话的 tick（这是 N2 主指标的原始信号）。

## 3. 必须记录的 4 个时刻（导出后补，或现场记在纸上）

| 时刻 | 字段 | 为什么要 |
|---|---|---|
| 提示出现 | 提示 tick + 当时 money / food / 户数 | 判断「信息」是否及时到达 |
| **首座食肆建成** | 建成 tick + 当时 money / food / 户数 | **本次复测的核心新增项**：若提示已提前而玩家仍磨很久，瓶颈是经济不是信息 |
| Lv3 达成 | tick | 与 Lv2 tick 相减即徘徊段 |
| 玩家说「无聊 / 不知道干嘛」 | 原话 + tick | c（目标感）是否独立病灶的唯一证据 |

前两项若导出 JSON 里没有现成字段，现场用纸记 tick（HUD 上有 tick 显示），别事后回忆。

## 5. 判读口径（供事后分析，别在现场用）

- **徘徊段** = `milestones.lv3 − milestones.lv2`，目标 **≤100**。
- **提示是否有效** = 提示出现后 → 首座食肆建成的间隔（对照 P4 实测 72 tick）。若间隔没缩短，说明提前触发不解决问题。
- **误触发检查** = 游戏顺畅的玩家不该看到 T1。若看到，是 `growthDelta=10` 定高了。
- 单人单局只是样本；**2 位不同玩家都要过线才算 PASS**，一位过线一位不过 → CONCERNS，需第三方裁定。
