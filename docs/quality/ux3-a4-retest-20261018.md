## 3. 根因：开局资源错配自陷（不是经济参数过紧）

v1.0 把 B 的卡壳读成「Lv2 段经济太紧」，**这是误判**。逐采样复核开局资金流向后，事实是 B 把 240 启动资金**一分不剩地全押在无收入建筑上**：

| 支出项 | 金额 | 性质 |
|---|---|---|
| 磨坊 ×3（tick 30，此时农田 = 0，无粮可磨） | 90 | 空转 |
| 拆回 2 座磨坊（返还 50%） | −30 | 自救 |
| 茅屋 ×2 | 20 | 人口上限 |
| 农田 ×4 | 60 | 只产粮，不产钱 |
| 林场 ×4 | 60 | 只产木，不产钱 |
| 粮仓 ×1 | 40 | 只存粮，不产钱 |
| **合计** | **240 / 240** | **收入建筑 0 座** |

**这不是参数问题，是决策后果。** 他唯一能变现的建筑是食肆（50 钱，Lv2 解锁），而他把钱在 Lv2 之前就花光了；此后只能靠市税 0.05×4 户 = 0.2/tick 攒钱，最后靠**拆除（返还 50%，`rules.js` `demolishRefundRate`）**回款自救——这条路径真实存在且他靠自己找到了（自述「看了提示说拆建筑有钱，才拆的」）。

**因此：「把市税/造价调松」是错误的处方。** 它会直接删掉本作当前唯一有分量的决策（先铺产能还是先留现金），并且触碰 D-C1 冻结令、威胁 V1 仅 0.74 分的余量。v1.0 的「甲：经济立项」建议**撤回**。

**但数据里仍有一条不涉及数值的真实缺口**：T1 在 tick 182 弹出时，B 身上只有 8 钱，而提示的处方是「建食肆（50 钱 + 25 木）」——**提示给了当下买不起的处方，且未提恢复路径**。他花了 101 tick 才靠拆建摸到出路。这不是「提示太晚」，是「提示不可执行」。

## 4. 与 B 的失误无关、但本轮确证的三条

1. **提示处方不可执行**：T1 在 tick 182 触发（Lv2+50，很及时），但当时 B 只有 8 钱，提示说「建食肆」而食肆要 50；提示未提「钱不够怎么办」（市税 0.2/tick、拆除返还 50%）。他 101 tick 后自救成功。**这是文案覆盖面的缺口，不涉及任何数值。**
2. **等级回落惩罚**：B 在挣扎期（tick 300）从 Lv2 **跌回 Lv1**（繁荣 18<20）。对挣扎中的新手是双重打击；A 未经历。此前判定组未观测过，建议单列议题。
3. **超建食肆模式再现**：B 建了 11 座食肆致 tick 360 断粮，与 P5 同款。
4. （结构观察，非 B 的过错）**木材没有变现出口**：B 终局木 923、自述「反之木多」。4 座林场把钱变成了死资产，而全流程唯一变现金径是食肆/杂货摊。是否属设计意图待定，进 backlog，不动。

## 7. 修订记录

**v1.1（22:10）**：v1.0 判「Lv2 段经济过紧 → 建议经济立项」，被用户当场质疑（「他是不懂规则，上来造了好几个林场导致没钱，不是符合逻辑吗？」）。复核逐采样 `buildingBreakdown` 与造价表后确认**用户判断正确**：

- B 的开局不是「乱点」，是**系统性把钱花在成本中心**：tick 30 先造 3 座磨坊（90 钱，此时农田 = 0，无粮可磨）→ 拆回 2 座 → 再铺 4 农田 + 4 林场 + 1 粮仓。到 tick 150，240 启动资金**精确花光，收入建筑 0 座**。
- 这个结果正是本作当前唯一有分量的决策在起作用：**先铺产能还是留现金**。把它「修掉」等于删掉决策。
- v1.0 的错误方法：只看 `money` 曲线（1~25）就下「经济过紧」结论，没有回看支出结构。**教训：钱少 ≠ 参数紧，必须同时看钱花到哪去了。**
- 保留的 v1.0 有效结论：T1 触发及时（Lv2+50）、无误伤、B 自救依赖隐藏机制（拆除返还）——后两点转为 §4-1「提示处方不可执行」的文案缺口。
