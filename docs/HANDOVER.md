# 项目交接文档 —— 《市井繁华》（暂定名）

> 交接时间：2026-10-17 · 阶段：P1.5 灰盒可玩版已完成并通过验收
> 制作人：范可控 · 设计：游有方 · 技术：柯桥良

## 1. 这是什么

宋代市井题材的城建经营模拟游戏，HTML5 网页版。机制参照《满庭芳·宋上繁华》（建造+资源链+人口/繁荣度），**美术、文案、建筑名、数值全部原创**，仅借鉴机制思路。当前为灰盒色块阶段，无正式美术。

## 2. 当前状态：可玩，核心循环已闭合

- 32×32 网格地图（含沃土/林地地形约束），相机缩放/平移
- 9 种建筑，4 级繁荣度阶梯解锁（Lv2=20 / Lv3=50 / Lv4=100，Lv4 即竖切片通关点）
- 双资源链自动流转：粮线（农田→磨坊→食肆→铜钱）、木线（林场→木匠铺→杂货摊→铜钱）
- 人口系统：空房+食库存>10 每 5 tick 迁入 1 户；食耗尽迁出（保底 1 户）；工坊商铺占劳力
- 市税：每户每 tick +0.05 铜钱（v0.3 新增，防资金死锁的保底收入）
- 断链警示：缺料红 / 缺人黄；HUD 显示资源、人口、市税/商业收入拆分、繁荣度进度条
- 暂停/1×/2× 变速；localStorage 最小存档（每 30 tick 自动 + 手动按钮）
- 中文建造失败提示；繁荣度升级 toast

## 3. 如何运行

```bash
cd d:/code/life
npm install        # 首次
npm run dev        # 开发试玩 → http://localhost:5173
npm run test       # 开发自测（当前 63/63 绿）
npm run build      # 构建 → dist/（纯静态，任意托管即玩）

# 独立验收套件（与开发自测分离，使用专用配置）
npx vitest run --config vitest.verification.config.js   # 当前 32/32 绿
```

**注意**：`npm run test` 默认排除 `tests/verification/`（见 vite.config.js），验收套件必须用上面那条命令单独跑。两者职责不同：开发自测防回归，验收套件证玩法。

## 5. 验收证据（关键数据）

- **初始资源自然通关**：bot 从 240 钱/60 木/20 粮/20 食/0 人口起步，tick 11 到 Lv2、286 到 Lv3、**504 到 Lv4 通关**（终局 57 户/55 建筑/繁荣度 100）
- **注入铜钱对照**：Lv2→Lv4 链路独立验证可走通（82 tick 通关）
- **资金归零可恢复**：耗尽后仅靠市税 77 tick 攒回食肆造价（最坏情况 1001 tick），0 是可穿越下界
- 两条历史死锁（启动锁死、资金死锁）均已在 v0.2/v0.3 修复并有用例看守

## 6. 遗留事项（按优先级）

### 6.1 待用户实测反馈（阻塞下一步调参）
**节奏偏快**：bot 实测通关约 8.4 分钟（tick 504），低于设计目标 25 分钟——bot 是最优玩家代表下限，但设计侧（游有方）已预判熟练玩家约 13 分钟。**需要真人试玩数据**：记录到达 Lv2/Lv3/Lv4 的真实时刻。若偏离目标超 30%，只动一个杠杆——**提高解锁阈值**（Lv3 50→60 或 Lv4 100→120），不动经济比例。杠杆优先级与理由见设计案 8 章。

### 6.2 已知非阻断问题
- **浮点尾差**：铜钱 float 累计，最坏路径回血比理论值多 1 tick（49.999… 尾差）。若介意可改内部存"厘"（整数分），需设计侧拍板。
- **食肆抢劳力边缘**：人口=1 时先放食肆会抢磨坊劳力致其空转，玩家可拆除恢复；已有食链优先结算缓解，未完全杜绝。
- **茅舍空屋刷分口**：空屋也计繁荣度，但茅舍不产钱撑不起后期，经济自然回归钱链，竖切片不处理。

### 6.3 下一阶段候选（P2，均未启动）

## 7. 纪律备忘（给下一位接手者）

1. **数值改动必须过验收推演**：改 config 后必跑 `tests/verification/progression.test.js` 的 bot 通关推演，确认仍能自然到 Lv4。本轮两条死锁都是数值表"看着合理"但数学上走不通，别信纸面。
2. **验收与开发自测分离**：`tests/verification/` 是独立基准，开发者不许改它来让自己的代码通过（改了等于自己给自己判卷）。
3. **版权红线**：只借鉴机制，所有文案/名称/数值保持原创，不引入《宋上繁华》任何资产。
4. **core 是规则唯一权威**：任何玩法判定（如解锁等级）必须落在 `core/`，UI 只做展示层。
